# 使用与边界

## 安装与开始使用

```bash
hermes plugins install vc1235-ui/oil-hermes-title --enable
hermes oil-title doctor        # 自检：会话库、命名规则文件、会话解析
```

本插件是原生 Hermes 插件（`plugin.yaml` + `__init__.py` 的 `register(ctx)`），
适用于所有会调用 `post_llm_call` 的会话：交互式 CLI、桌面 app、gateway（Telegram/Discord/…）、
TUI。命名调用使用宿主提供的 `ctx.llm`（当前活动模型与鉴权），**无需另外保存 API Key**。

安装后在新会话里正常聊天即可。命名在后台独立调用里完成，不往对话里追加任何消息，
也不占用 `plugins.hook_callback_timeout`（默认 30s）的预算。

需要信任的行为：读取当前会话最近几轮对话 → 调用一次模型 → 通过 Hermes 的会话标题接口
写入标题。不恢复原会话、不发消息、不直接改写数据库结构。

## 命名方式

标题固定为「类别 emoji + 对象｜目标」：对象在前，目标在后，恰好一个全角分隔符。
类别按**持续产物**选择，不随「修复」「发布」「继续」这类临时动作切换。
旧标题结构不对时允许一次性迁移，之后保留准确的对象措辞和主线；信息不足时保留原名。

标题跟随最近几轮**用户**消息的主要语言，保留产品名与技术名词；
助手回答、代码与引用原文不决定标题语言。偶尔一句外语不切换，持续换用另一种语言才迁移。

| 类型 | emoji |
| --- | --- |
| 内容制作 | 🎬 |
| 工具开发 | 🧩 |
| 对比调研 | 🔎 |
| 方法整理与文档 | 📝 |
| 日程安排 | 📅 |
| 页面设计 | 🎨 |
| 环境配置 | ⚙️ |
| 一般讨论 | 💬 |

默认参考最近 5 轮有文字的对话。只有问候或确认、没有实质目标时直接保留标题，不调用模型。
临时排错、术语解释、测试或「继续」不会自动变成新的主要目标。
命名规则集中在 `prompts/naming.md`，可通过 `settings.style` 追加自定义风格。

已经稳定、且内容基线未变时，新增的「好的」「收到」「继续」等纯确认可免模型跳过，
默认最多连续两轮（`confirm_skip_limit`），之后重新判断一次。
同一段内容重复触发（重试、回声）不会重复调用模型。

## 控制方式

直接对 Agent 说（推荐，会话 id 自动带入）：

```text
「预览这个话题的新标题。」
「就用这个标题。」
「固定这个话题的标题。」
「把标题改成 <X>。」
「暂停自动命名。」/「恢复自动命名。」
「看下命名用量。」
「预览可以归档的闲置话题。」
```

也可以自己跑：

```bash
hermes oil-title status
hermes oil-title preview --session <id> [--json]   # 默认只预览
hermes oil-title apply   --session <id>            # 才写入
hermes oil-title rename  --session <id> "<标题>"
hermes oil-title lock    --session <id>
hermes oil-title unlock  --session <id>
hermes oil-title pause | resume
hermes oil-title usage   [--days 7] [--json]
hermes oil-title archive-preview [--days 3] [--json]
hermes oil-title backfill [--days 14] [--apply] [--include-user] [--include-automation]
hermes oil-title restore [--file <备份.json>] [--apply]
hermes oil-title doctor
```

`backfill` 不带 `--apply` 时**不调用模型**，只列范围与跳过原因；`--apply` 前会自动写标题备份，
`restore` 可整体回滚（标题文字与权限都还原）。默认保护 `user` 权限标题、跳过自动化会话。

会话内斜杠命令 `/oil-title status|pause|resume|usage|archive-preview|doctor` 覆盖不需要会话 id 的动作；
`preview / apply / lock / unlock / rename` 是单会话动作，斜杠命令拿不到当前会话 id，
用自然语言让 Agent 执行，或显式传 `--session`。

`--session <id>` 放在子命令前或后都行（`hermes oil-title --session X lock` = `hermes oil-title lock --session X`）；
不带就取环境变量 `HERMES_SESSION_ID`（Agent 在会话内调用时自动指向当前会话）。

`preview` 只预览。`apply` 才写入，并按权限规则读回核验。

## 数据与并发边界

`usage` 汇总插件自己的调用账本，按日期落在
`~/.hermes/plugin-data/<namespace>/usage/YYYY-MM-DD.jsonl`，
只记时间、用途、模型、会话 id、用量、耗时和状态，**不记标题原文、不记对话内容**。
未知用量记为未知，不当作零，不换算账号额度。命名调用本身也记在 Hermes 的会话账上。

配置与每会话状态：`plugins.entries.oil-hermes-title.settings`（`~/.hermes/config.yaml`）
与 `~/.hermes/plugin-data/<namespace>/state.json`（最多保留 400 个会话的记账，按最近使用裁剪）。

后台默认最多同时运行 2 个命名调用（`max_parallel_workers`，1-8）；闸门满时本回合直接跳过，
不排队、不阻塞对话。同一会话的写入走宿主接口的 compare-and-swap，读到手动标题后立即放弃写入。

## 兼容性与限制

- 一次性运行（`hermes chat -q`）：进程在后台命名返回前退出，标题不会落下。长驻会话不受影响。
- 自动化来源（cron / kanban / tool / batch / subagent / oneshot）默认跳过命名。
- 侧边栏标题没有实时推送：插件写库后，标题在下一次会话列表/信息刷新时可见。
- 标题全局唯一、上限 100 字符；撞名自动加 `#N`，仍冲突则保留原标题并记 `conflict`。
- 多 profile：按当前 profile 解析 `state.db`；显式指定可用 `settings.state_db_path`。
- 离线：配置与暂停可以查看，生成标题需要能连上模型服务。
- **历史会话回填**：`hermes oil-title backfill --days 14` 先用**不调用模型**的范围预览列出会改哪些；
  `--apply` 才执行，执行前自动把原标题写进 `~/.hermes/plugin-data/<ns>/title-backups/*.json`。
  默认**保护 `user` 权限标题**（不覆盖你自己起的名字）并**跳过自动化会话**（cron/kanban/tool/
  batch/oneshot/subagent）；要一并处理需显式 `--include-user` / `--include-automation`。
  回滚：`hermes oil-title restore --file <备份.json> --apply`（文字与权限都还原）。

## 开发验证

```bash
PYTHONPATH="$HOME/.hermes/hermes-agent" ~/.hermes/hermes-agent/venv/bin/python -m pytest tests/ -q
hermes plugins doctor . --ci
```

结构自检、模型实测、真实钩子触发是三类证据，不能相互替代：

- `hermes plugins doctor . --ci` 证明清单、导入与注册契约。
- `pytest tests/` 覆盖命名判别、标题格式校验、权限写入（含同 rank 重写必须降级的回归）、
  编排门槛，以及 CLI 参数解析（`--session` 在子命令前后都要能解析）。
- 真实触发需要在已启用插件的新会话里跑一轮，然后在 `agent.log` 里看到
  `oil-hermes-title: 已排入后台命名`，再看标题与 `hermes oil-title usage`。
